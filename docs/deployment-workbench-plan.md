# 部署方案工作台实施方案

## 目标与验收

用户从空白页面选择产品模板、主机与数据库安装，填写数据根目录，保存草稿，检查并生成配置，预览操作，然后提交平台任务；无需手填环境 ID、YAML 路径或部署目标。刷新后草稿与环境关联仍存在。接管已有集群只能检查、登记和健康验收，不能进入初始化。不会为了实现界面而重建现有数据库。

## 配置模型

- 身份：自动生成稳定 environment_id；名称独立可改，测试／任务／报告引用 ID。
- 来源：新建模板、接管已有实例、导入 pgcluster YAML。首批产品模板为等保三节点、FBase 多活六节点、fbasecman 十四节点。
- 主机与安装：目标主机、本机或 SSH；数据库安装根目录 PGHOME；安装探测从 PATH、常见安装目录、运行进程和指定数据目录的 postmaster.opts 收集候选，附来源、版本、工具完整性。标准布局派生 bin 目录，不重复输入。
- 实例：模板生成名称／端口／目录，节点级可覆盖；碰撞以同一主机的端口和规范化目录检查。
- 初始化与产品能力：数据库名、初始化用户、复制关系、插件／License、产品参数。现有回归模板保留其测试兼容约束（postgres 初始库／用户和固定组名），不能在 UI 暴露暂不支持的自由修改。
- 高级 PostgreSQL 参数：提供 JSON 对象覆盖；平台保留端口、数据目录、预加载和复制模式等结构参数的所有权，语义配置由产品编译器维护。
- 凭据：支持显式 SSH 用户、端口、私钥文件引用与连接超时，也可复用系统 SSH 配置和 agent；不保存密码。
- 自动接管：输入同一主机的完整数据目录列表，只读探测安装、系统标识、端口、主备角色、上游与 MMR 元数据，生成可审阅 YAML。主备按系统标识及上游端点双重匹配；MMR 保留实际组和成员名称。运行中的 MMR 需允许 postgres 数据库的 postgres 用户只读连接；离线普通主备可识别，离线 MMR、缺成员、角色冲突或跨主机成员明确阻止自动生成。跨主机集群可导入 YAML。

## 单一来源与存储

部署草稿是期望配置，保存在 data/deployment-drafts/<id>.json（schema_version、revision、spec）。产品提供模板与编译器，平台核心不按产品 ID 分支。每次生成使用新的不可变计划目录 data/deployment-plans/<plan-id>/，保存 plan.json、pgcluster.yaml 及产品辅助文件。环境登记指向已关联配置版本。运行状态来自探测，不能反写期望配置。

## 检查、计划与执行

1. 表单校验：绝对路径、名称、端口、节点重复、产品模板选择。
2. pgcluster 结构校验与目标解析，确认实例与复制关系。
3. 目标主机只读探测：工具是否可执行、版本一致性、所需扩展／License 存在、端口是否占用、数据目录是否非空、PG_VERSION 是否匹配。失败／超时按检查失败处理，不推断空闲。
4. 新建：存在数据或端口冲突即阻止创建；接管／导入：所有节点必须存在数据库数据目录并且版本兼容，不提交 deployment.create。
5. 计划展示按节点列出动作和检查结果；导入配置与当前部署配置出现语义差异时切换为差异计划——普通参数、物理备库扩缩容及备库端口／目录／跨主机迁移可通过带检查点的变更任务执行；独立物理复制组主节点可先建副本、核对关闭 WAL 栅栏后迁移；MMR/Citus 成员增删可创建或退役独立主备组，逻辑链路可增删或替换订阅端。主库迁移同步关联 MMR/Citus/逻辑订阅端点；目录迁移要求实际延续全部逻辑槽及所需 WAL，不能只凭 failover 声明。现有成员任意重命名仍阻止发布。跨目录备库迁移需独立新复制槽，新副本追平后才退役旧副本。不把结构校验等同于真机检查。
6. 应用时核对草稿 revision、配置摘要和环境基线，重新执行目标检查；登记环境自动关联生成文件。若入队部署，任务冻结配置快照与摘要，worker 再验证摘要与节点检查，避免配置修改或排队期间状态变化导致执行旧计划。
7. 执行沿用平台任务、日志、取消、环境锁和状态观测。完成后用健康检查验收；初始化失败不自动删除数据，不声称自动回滚。重试须重新探测并生成方案。

## 界面

新增“部署方案”入口，提供草稿选择和四步工作台：基本信息／来源、主机与安装、节点与高级参数、检查结果与操作预览。生成文件可预览和下载，不占日常拓扑页面；已有环境可以从当前配置导入为草稿。正常环境登记仍可用于仅数据库连接场景，空配置环境明确提供创建／关联方案入口。

## 实施批次

A（本批）：三模板、产品编译边界、自动 ID、草稿、安装探测、节点编辑、只读检查、不可变计划、文件预览、自动环境关联、任务快照及新建／接管执行分流、单机／当前同用户 SSH、前后端和浏览器验收。
B（已实现）：显式主机／凭据资源、多主机安装分配、语义差异计划、分步骤检查点及 React Flow 自由拓扑建模；支持普通参数应用、物理备库扩缩容、备库端口／目录／跨主机迁移。恢复界面可继续原计划；新增成员可初始化独立主备组，MMR 正常退出、Citus 排空分片后退役，逻辑链路变更保留业务表；独立主库迁移使用关闭 WAL 栅栏和恢复检查点。关联复制端点在主库切换后同步更新并验收；非 failover 逻辑槽不允许随目录迁移丢弃，保留原目录的端口变更仍可执行。详见 current-functional-status.md。

C（自动接管）：已有实例探测与 YAML 生成已实现，复用现有草稿、检查、计划与健康验收。探测本身不启动实例、不修改配置或数据，不自动绑定固定回归模板。

## 验证约束

使用隔离 FileStore 与伪数据库工具测试编译、只读探测、端口／数据目录冲突、失效计划、配置摘要变化、导入和任务冻结；浏览器验证完整工作流，不执行真实初始化。真实部署需用户选择并审阅具体生成计划后触发。现有四环境的配置和数据库不被本批开发覆盖。
