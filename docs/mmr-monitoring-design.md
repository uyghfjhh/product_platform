# FBase MMR 监控实施方案

状态：首批即时观测已实现，完整图形监控建设中 · 2026-10-03

## 目标与范围

监控工作区需要回答：哪个成员或方向异常、停在发送／接收／应用的哪一端、冲突采用了什么结果、故障有没有恢复。沿用数据库管理入口、平台主题、环境配置和唯一 Studio。MMR 成员身份与承载它的 PostgreSQL 实例分别建模；物理备库挂在成员下面，不统计为额外多活写节点。

当前界面示意见[数据库监控设计图](database-observability-plan.md#多活监控源码核对后的新版)。四张图是模拟数据，本方案定义进一步优化后的实施行为；图中尚未呈现的拓扑和字段差异高亮不视为已完成。

## 页面与排查路径

### 概况：拓扑成为主视图

中心展示实际成员及有向逻辑复制边，每条边分别标明接收证据、应用证据、采样时间和异常原因。物理主备边采用不同线型和文字标识。成员卡片区分登记状态、实际主备角色、只读设置和复制运行证据，不使用一个绿色 ACTIVE 代表全部正常。

拓扑数据来自可见成员、订阅映射及平台实际实例记录。元数据与实际角色不一致时并列显示；无法确定承载实例时显示待确认，不猜测节点身份。配置没有对应方向时显示未配置，不作为故障边。

首页仅保留异常列表、最需要关注的方向、槽保留趋势和冲突热点。点击边打开链路详情，点击成员打开生命周期和观察者对照，点击冲突热点保持时间窗进入冲突专题。

### 链路详情：完整证据链

固定顺序：源成员 → 发布／复制集 → 源端槽 → 目标订阅 → 接收运行统计 → 应用／origin 证据 → 错误与恢复记录。

每段展示实际对象标识、读取位置、采样时间和有效性；num_writers 单列为配置，不显示为实际存活进程数。发布／槽名称必须从对象映射读取，不凭命名约定拼接。订阅禁用、进程缺失、采集失败分别解释。

接收 PID 关联 pg_stat_activity 时验证订阅与实例，PID 复用不能串接历史错误。只能确认位置推进时显示位置推进证据，不升级为业务数据一致。received_lsn、origin 位置的坐标与语义核实后才做同源差值；目标本地 WAL 与源端 WAL 不相减。没有准确应用时间延迟时显示未提供。

### 冲突：字段对比与处理结果

列表按时间、订阅、表、类型、策略筛选；点击事件展示 key_tuple、local_tuple、remote_tuple、apply_tuple 原始内容，不做脱敏。

本地／远端 JSON 按字段并排对比，高亮不同值；区分字段缺失、JSON null、SQL NULL 和原生标记。对于 JSON 对象比较键值，数组保持顺序，不通过字符串排版差异制造冲突。标记引用本地全行时提供跳转说明；解析不了的原值完整展示。

apply_tuple=local／remote 时指出采用哪一侧并展示对应历史行；none 只说明没有应用行标记，不自动判成功或恢复。若数据库原值含包装字符或其他格式，保留原值，适配器验证格式后解释。冲突策略读取各成员实际配置，源码安装默认仅作为参考。来源成员通过 sub_id 与订阅映射核实，不把 local_tuple_node_id 当作远端来源。

### 成员、进程与复制范围

生命周期保留原生 NONE、CREATED、JOIN_START、DATASYNC、CATCHUP、ACTIVE、PART_START、PARTING、PART_CATCHUP、PARTED；阶段示意不是完整状态转换图。不同观察者的登记状态按行对照，标明不可访问和样本时间。

进程专题展示角色原值、PID、等待事件、原始错误消息和上下文、发生及恢复时间。无恢复记录仅标记待核查，联合当前运行证据判断；已恢复错误留在历史，新的采样故障独立报告。

复制范围展示复制集四类操作开关、表成员、set_iscopydata、set_sync_state，并与 pg_subscription_rel 的运行状态分列。两个状态来自不同对象，不混用映射。源码中表状态约束包含 i/w/s/c/r，而注释未完整解释 r，实施前追踪对应状态写入路径；未验证的值原样显示。

## 数据与采集契约

产品查询与状态解释放在 `products/fbase-database/` 的监控扩展；公共采集调度、历史存储和图表由平台负责。复用现有产品 provider 和数据库连接配置，不另建环境注册表或 SQL 工具。

建议规范化对象：MemberObservation、DirectedLinkObservation、SlotObservation、ConflictRecord、WorkerErrorRecord、ReplicationScope。统一包含 environment_id、数据库身份、成员／观察者身份、observed_at、来源版本、有效性与错误原因。方向使用组、数据库、origin_node_id、target_node_id 和订阅身份联合识别，避免跨组、跨库或重建订阅串数据。

- 5 秒：轻量运行统计与位置；有限并发、只读事务、独立超时。
- 30 秒：成员、组、订阅、复制范围配置；部署任务完成后触发提前刷新。
- 按需：冲突原始行、完整错误上下文、表级详情、show_node_info 综合诊断。
- 时序历史存计数和位置证据；大 JSON 不进入每五秒采样。断点、统计重置、角色切换重新建立基线。

冲突表没有由本轮安装 SQL 确认的唯一事件键或时间索引；不能简单使用 local_time 游标保证不漏不重。先检测实际索引、规模及日志完整性，用有预算的时间窗查询和稳定排序；无可靠分页／聚合条件时显示部分结果和统计不可用。不得自动给业务库建索引。错误表是可更新记录，应重读有限窗口并检测字段变化，不只按新增时间扫描。

所有时间窗统一采用 UTC 存储、页面按用户时区显示。跨节点时钟不同可能影响事件排序，原始时间和采集时间同时保留。

## 状态判断与恢复

| 情况 | 页面判断 |
| --- | --- |
| 无权限、超时、对象缺失 | 不可观测，显示原因；不填零、不判节点宕机 |
| 订阅登记禁用 | 已禁用；是否预期结合任务和配置，不自动判故障 |
| 有接收进程但存在无恢复错误 | 接收存在、应用待核查；展示两个独立事实 |
| 低负载、位置不变 | 无进展样本；没有源端变化不能推断应用停滞 |
| 同源待处理位置差持续增长且运行证据异常 | 链路异常，附观测窗口与原始证据 |
| 内部槽 inactive | 按用途与预期解释；未知槽待核查，不直接告警 |
| recovery_time 已记录且当前采样正常 | 历史错误已恢复；恢复采样时间另列 |
| 登记状态分歧 | 状态分歧需诊断，不自动认定脑裂 |

告警使用连续样本和恢复滞后，阈值可配置；恢复阈值与触发阈值分别定义。监控不执行订阅重建、退出成员、清理槽或自动杀会话。

## 实施顺序与验收

1. 探测实际版本、目录对象、字段、权限；建立成员／订阅／实例映射，先验证证据口径。
2. 实现拓扑、方向详情和状态判断，复用平台历史采集；保证一个节点失败不拖垮全环境。
3. 实现冲突字段对比、错误恢复、生命周期与复制范围详情。
4. 最后接入可验证的应用速率、时钟检查及 fbasecman 路由。Raft、CAMO、Commit Scopes 和分位延迟不作为无来源的默认功能。

验收包括：ACTIVE 但单向异常；进程存在但错误未恢复；低负载不误报；历史恢复记录与新故障并存；禁用／权限不足／超时区别；主备切换保持成员身份并切换实例；订阅重建不串旧历史；表状态两套字段不混用；冲突 JSON 缺失/null/标记及原始内容完整显示；错误记录更新不伪造发生率；桌面与窄屏可排查。使用测试夹具及受控环境，不在生产主动制造故障。

## 当前实现进度

已建立独立「数据库监控」导航；数据库管理仅保留唯一 Studio。监控支持环境选择、跳转指定实例 Studio、启用／停止后台采集。默认未启用，启用后关闭浏览器仍继续采样；多 Web 进程使用共享锁及最小采样间隔避免重复。

后台每环境间隔至少 15 秒（采集较慢时会延后），FBase 扩展执行只读、超时、分项独立采集。SQLite 保存 24 小时历史；页面查看最近一小时内最多 120 个样本，启动后不足两个有效样本显示空状态。最新快照包含最近错误和冲突原始内容，时序历史只保存运行、复制槽、发送端及 origin 位置。配置或端点指纹变化时清除该环境旧曲线基线。

页面已有配置拓扑边与实际主备角色对照、实例概况、物理发送／写入／刷盘／回放阶段、有向订阅与接收进程关联、WAL 保留趋势、最近一小时最多 30 条冲突原始记录及字段差异对比、最近 50 条进程错误与恢复字段、最多 200 条复制范围记录。数据有限额，不宣称是完整冲突率或全量表清单。重启和缺失样本断开保留 WAL 曲线；超过一分钟的样本显示新鲜度警示。

已增加同一发送连接的发送／写入／刷盘／回放 WAL 位置推进速率、三段位置差值，以及 WAL 保留阈值和连续样本／恢复滞后告警。逻辑与物理发送端按槽类型分别展示；无法确定类型时保留原始证据。

已完成实际成员与跨实例链路合并、拓扑下钻及采样变化事件。已增加部署任务生命周期与数据库观测的联合时间线。尚缺可靠来源的指标：准确业务应用时间延迟／追平估计，以及并行 writer 的连续提交水位。当前显示原始位置与证据，不宣称已经追平或业务数据一致。真实环境已完成只读采集核验，异常注入与浏览器验证使用隔离环境。


## 复制进度及告警验证补充（2026-10-03）

速率由产品扩展计算，使用每项统计的采样时间；同一节点、sender PID 与 backend_start、槽身份、服务器启动时间、角色与控制文件时间线共同建立基线。计数倒退、任一位置缺失、采样间隔超过 45 秒或时间线不可观测时速率无效，缺失不填零。阶段差值只比较发送端同源坐标；当前 WAL 采样早于发送端，故不计算当前 WAL 减 sent_lsn，避免非同时采样的负差值。

FBase 对应 PG worker 的提交处理设置 replorigin_session_origin_lsn，origin 视图分别输出 remote_lsn 与 local_lsn。本地源码及真实订阅映射核验后，单 writer 主库可以显示 received_lsn 与同订阅 origin remote_lsn 的源 WAL 坐标距离；它可能包含跳过处理，不代表业务行一致、精确待应用数据量或时间延迟。并行 writer 与备库不计算该指标。

WAL 告警支持每环境 retained_mib 和 consecutive_samples；恢复需低于阈值的 80% 并连续确认。lost 立即告警，unreserved 或保留超阈值连续确认。不可观测或槽消失标记未知，不自动恢复。告警规则变更仅重置告警确认窗口，保留位置历史，监控不自动删除槽。当前为页面内告警，没有外部通知。

已对 192.168.0.15 的四个已接管实例执行两轮只读采样，间隔 15 秒：四实例均可连接，四个发送连接得到有效位置推进速率，MMR 订阅 origin_name 与 origin external_id 映射吻合。错误历史存在两条超出正常日期范围的时间戳，已改为原始文本读取并提供 time_valid 标志；不使用异常时间戳判断恢复。未注入故障、未写业务表、未执行长时间压测。此验证覆盖采样和计算，不证明所有异常场景已在真实环境验收。


## 实际拓扑与链路下钻验证补充（2026-10-03）

成员承载关系来自 fdd.mmr_local_node 联合本地成员、复制组 UUID 和数据库身份；实际主备角色来自运行时 recovery。多个主库声明同一成员身份时保留歧义，不猜测承载者。只合并实际主库上的本地目标订阅，物理备库上的复制元数据不重复画成多活写入成员。

MMR 方向独立关联源端 logical slot、active_pid 与 sender、目标订阅及主接收进程。connected 仅表示这组连接证据存在，不等同于追平。禁用配置、采集不可观测和进程／槽缺失分别显示。物理链路由接收端 sender_host / sender_port 和两端 system_identifier 核对；127.0.0.1、::1、localhost 解释为接收实例所在主机。无法唯一映射地址或实例身份时保留未知。实际方向和部署配置分别标记。

拓扑边与文字入口均可打开链路抽屉：源端槽 → 发送进程 → 目标订阅／物理接收来源 → 接收统计 → origin → 对应订阅的冲突和错误。发送进程无法唯一关联时显示未确认，不把同机其他进程冒充链路进程。

观测事件保存最近 24 小时的角色变化、启动时间变化、链路状态和 WAL 告警状态变化；最多返回 100 条。事件时间是采样发现时间，不是精确故障发生时间。未与平台部署任务因果关联，也没有外部告警通知。

真实环境只读复核已确认 192.168.0.15 的两条 MMR 方向和两条物理主备链路。受控数据测试覆盖采集失败、system identifier 不匹配、重复主成员身份、提升后成员承载实例变化、远端 loopback 解释，以及不可观测样本不制造角色切换事件。浏览器覆盖点击链路打开完整证据。未在真实环境执行断连、重启或切换故障注入；这部分仍待独立测试环境验收。


## 历史、链路告警与隔离验收补充（2026-10-03）

历史支持 15 分钟、1 小时、6 小时、24 小时及 7 天。原始样本保存 24 小时；有效位置速率和槽保留量做分钟聚合，保存 7 天。长时间窗口按时间桶加权合并有效样本计数和总和，并保留最大值；每序列约 120 点，最多返回最近活跃的 128 序列。图中实线为有效样本均值、虚线为峰值；缺失桶断开，不填零。重启、角色、发送连接、时间线各自分组。分钟聚合从功能启用后积累，不补造既有历史。

链路中断采用连续样本触发／恢复。MMR 使用已解析的本地目标订阅、源端槽和接收进程证据；禁用是配置事实，不冒称故障。物理链路仅在先前已确认槽归属、源实例启动周期稳定且对应物理槽 inactive 时确认中断；目标不可访问不直接判宕机。身份歧义、统计权限不足和映射未知不算健康，也不自动恢复。

隔离真实验收使用 pytest 临时 PGDATA 和独立端口，未读取或修改已登记环境。已验证停止备库 → 源端物理槽断开 → 连续告警，备库重启 → 连接恢复 → 连续恢复，以及原主停止、备库提升后旧链路不继续标记 connected。测试约数秒，仅显式指定 PLATFORM_TEST_POSTGRES_HOME 时执行；普通测试默认跳过。测试文件为 tests/test_monitoring_streaming_live.py。

进一步源码核对发现 fdd_subscription.c 创建记录时将 num_writers 固定为 1，实际并行行为由 PG 订阅 streaming、fdd_streaming_parallel 和本地成员 streaming 模式共同决定。worker.c 的启动逻辑与 fdd_metadata_cache.c 的成员 streaming hook 已核对。因此 num_writers 仅展示登记值，不作为串行证明。

采集 apply_configuration 联合 pg_subscription 和本地成员配置，缺少字段或权限时进度不可计算。只有订阅关闭 streaming，或明确串行 streaming 配置且无并行配置，并且当前可观测主应用进程恰好一个时计算接收到 origin 坐标距离。并行或未知模式展示配置和进程证据，不虚构连续应用水位。192.168.0.15 两个主成员经只读核验均为 streaming=false，因此仍可展示串行坐标距离；没有在现有环境切换并行配置。


## 部署事件与成员分歧告警补充（2026-10-03）

联合时间线读取当前环境最近最多 100 个部署任务，投影创建／启动／结束时间与最终状态，和同时间窗的数据库采样事件一起排序，最多返回 100 条。可直接打开原任务查看完整日志与证据。关联依据只有环境和时间，不把相邻事件自动解释为因果，也不把任务成功当作数据库已恢复。任务查询在 limit 之前过滤环境，不被其他环境的任务挤掉；投影做短时缓存，避免每个浏览器五秒轮询重复扫描任务索引。

成员状态对照只使用运行角色为主库的观察者，按组 UUID、数据库和成员 ID 分组。不同状态明确标记分歧；主成员观察不足两个、缺少 ACTIVE 成员观察或权限不足时证据不足，不填健康。成员分歧连续样本触发告警，一致状态连续确认才恢复，未知观察不自动解除告警。此告警是登记状态分歧，不是脑裂或数据不一致结论。

已对 192.168.0.15 只读核验：两个主成员都能读取逻辑应用进程视图，两个成员的登记状态在主观察者间一致；备库不重复参与主观察者表决。

进一步核对 src/backend/replication/logical/launcher.c：pg_stat_get_subscription 在 FDDSP 路径显式跳过 parallel apply worker；GetLeaderApplyWorkerPid 是内部函数，在本轮核对的源码中未发现稳定 SQL 调用接口。applyparallelworker.c 的事务状态／队列为共享内存内部实现，不作为可直接采集的公开指标。

因此新增 workers 视图采集 pg_stat_activity 的 logical replication worker／parallel worker、PID、状态和等待事件。它可展示实例级并行进程，但没有可靠映射时不将子进程归给某订阅。主进程计数不是全部 writer 数；只要实例存在并行 worker 或进程视图不可观测，就不计算串行坐标差。真正的并行连续提交水位需要产品提供只读 SQL 接口及运行语义验证，当前明确显示不可计算，不修改生产配置或内核源码。
