## 明确不自动执行的操作

- 任意重命名／替换现有复制成员，或者把主库迁移与参数、成员增删和其他节点变更混在一个计划中。关联复制端点迁移按上表支持，保留已有拓扑身份。
- 目录／主机搬迁时丢弃逻辑槽，或仅凭 failover 声明就提升副本。源端全部逻辑槽必须能延续，迁移副本必须实际持有槽、有效位置和所需 WAL；切换前复核槽集合，关闭 WAL 回放后再复核副本。普通 PostgreSQL 15 发布端的非 failover 槽不能这样搬迁，可保留原目录改端口；缺少重启 WAL 时源主库继续运行，复制事务不通过重建订阅或重置位置“补过”。
- 跨主机复制迁移继续使用仅本机可达的主机资源。审阅配置需为相关成员声明全局可达地址；原数据库中相对本机的 localhost DSN 在核对归属后更新。目标副本的逻辑接收进程在连接更新前保持停用，之后按原并发设置恢复（需要重启）；源端有未纳入方案的逻辑订阅时拒绝自动搬迁，不让复制过来的订阅误连其他数据库。
- 非数据库服务部署、分布式 worker、复杂权限和向量数据库不是当前设计首期范围。
- 当前设计没有自动数据库大版本升级、任意业务表历史数据覆盖或外部 CLI 并发控制承诺。

版本切换、部署变更与接管都是显式审阅动作；验证功能时使用隔离实例，没有把生产集群当作压测或迁移试验对象。

## 可重复的隔离真机验收

`tests/test_deployment_live.py` 在 pytest 临时目录创建自己的数据库，结束后停止这些实例。设置 `PLATFORM_TEST_POSTGRES_HOME` 可运行主库迁移和逻辑复制；`PLATFORM_TEST_MMR_HOME` 和 `PLATFORM_TEST_CITUS_HOME` 分别启用插件验收。未设置的项默认跳过，不连接已登记环境。Citus 排空测试使用真实分片搬迁，不以空 Worker 或模拟 SQL 代替。

示例：`PLATFORM_TEST_POSTGRES_HOME=/usr/local/pgsql15.4 .venv/bin/pytest tests/test_deployment_live.py -q`。插件安装必须与选择的数据库二进制匹配；测试使用该安装的动态库目录。
