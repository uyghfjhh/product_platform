# 问题记录

本文档记录已由当前源码和目标环境确认的“转测文档与产品实现不一致”项。
这些差异不能由自动化用例自行猜测或掩盖；每项均保留文档原文、实现证据、实际结果以及采用的测试处理方式。

## D-001：商密和TLCP认证转测.md / 1.2.2 密码存储 / FDD 构建禁用 `psql \\password`

**涉及转测文档和章节**：`商密和TLCP认证转测.md` / `1.2.2 密码存储`。

**文档原文**：第 232-240 行使用 `postgres=# \\password` 为 postgres 设置密码，然后检查 `pg_authid.rolpassword` 为 `SM3` 加 64 位十六进制摘要。

**产品实现**：

- `configure.ac:2599` 无条件为产品 C/C++ 编译参数加入 `-DFDD`。
- `src/bin/psql/command.c:396-403` 在 `FDD` 下对 `\\password` 输出 `This command cannot be used to change the password.` 并返回 `PSQL_CMD_ERROR`。
- 非 FDD 的原始实现会在 `command.c:2148-2162` 调用 `PQencryptPasswordConn`，再执行 `ALTER USER ... PASSWORD ...`。

**目标运行证据**：当前 FBase 15.15 二进制执行 `\\password` 被拒绝；隔离实例执行 `ALTER USER postgres PASSWORD 'AlterSm3-123'` 后，`rolpassword` 匹配 `^SM3[0-9a-f]{64}$`，且 `sm3` HBA 下正确密码可登录、错误密码被拒绝。

**自动化处理**：经确认，`mac.gm.sm3_authentication` 使用 `ALTER USER ... PASSWORD ...` 验证同一服务端密码存储和 SM3 认证结果；报告前置条件明确该替代原因。产品若恢复 `\\password`，应将用例补回文档原交互步骤。

## D-002：商密和TLCP认证转测.md / 2.3.10 导入证书 / `load_certificate` 参数数量和执行角色已变化

**涉及转测文档和章节**：`商密和TLCP认证转测.md` / `2.3.10 导入证书`。

**文档原文**：第 1216 行声明 9 参数 `load_certificate(type, usage, start_time, end_time, key_path, cert_path, user, cert_sin, cert_pass)`；第 1245 行以 postgres 调用该 9 参数接口。

**产品实现**：

- 已安装扩展和运行实例登记的函数签名为 10 参数：`cert_type, cert_usage, start_time, end_time, key_path, cert_path, cert_owner, cert_user, cert_sin, cert_pass`。
- `contrib/fbase_mac/src/tlcp/fdb_tlcp_common.c:4275-4285` 分别读取第 7 个 `cert_owner`、第 8 个 `cert_user`、第 9 个 `cert_sin` 和第 10 个 `cert_pass` 参数。
- `fdb_tlcp_common.c:4312` 调用 `fdb_ensure_sso()`；其定义在第 123-130 行，要求当前账户为 SSO。

**目标运行证据**：全新隔离 TLCP 集群可生成并导出 CA 和 server 双证书；以 postgres 调用当前 10 参数 `load_certificate` 返回 `operation is not allowed on current user`，提示 `Login as SSO to do the operation.`。

**自动化处理**：后续导入用例按当前 10 参数接口实现，并使用 SSO 执行导入；同时保留 postgres/文档 9 参数调用不符合当前产品接口的证据，不将其伪装为通过。

## D-003：商密和TLCP认证转测.md / 2.4.2 SSL测试 / 吊销证书执行角色不一致

**涉及转测文档和章节**：`商密和TLCP认证转测.md` / `2.4.2 SSL测试`。

**文档原文**：吊销步骤以 postgres 调用 `fdb_mac.abort_certificate(2, 10, '!Aa242260')`。

**产品实现**：`contrib/fbase_mac/src/tlcp/fdb_tlcp_common.c:4036` 调用 `fdb_ensure_sso()`；其定义在第 123-130 行，非 SSO 会报 `operation is not allowed on current user`，提示以 SSO 登录。

**自动化处理**：SSL 吊销与 CRL 用例以 SSO 调用当前接口；证书生成、导出和 TLS 连接仍按文档由 postgres 执行。

## D-006：三权分立功能转测.md / 5.3.1.1 / DBA 可修改 SSO 配置

**涉及转测文档和章节**：`三权分立功能转测.md` / `5.3.1.1 DBA用户管理功能`。

**文档原文**：在三权分立关闭时，DBA 仅可在 SSO、SAO 未设置密码时设置其初始密码；除此之外，DBA 对 SSO、SAO 的 `ALTER USER` 操作应被拒绝。

**目标运行证据**：`mac.separation_of_duties.dba_user_management_separation_off` 以 postgres 执行 `BEGIN; ALTER USER sso CREATEROLE; ROLLBACK;`，实际返回 `BEGIN / ALTER ROLE / ROLLBACK`，未产生文档期望的 `only sso can change itself's configurations` 错误。事务已回滚，测试未保留角色属性变更。

**自动化处理**：用例保留文档预期并标记为 `D-006`。同时继续执行 SAO 对应步骤以保留独立证据；不得将产品实际放行改写为通过。

## D-007：透明加密功能转测（陈群友）.md / 1.2 / TDE 不能通过 reload 动态切换

**涉及转测文档和章节**：`透明加密功能转测（陈群友）.md` / `1.2 透明加密算法动态切换`。

**文档原文**：设置 `tde_encrypt = plain` 后执行 reload，透明加密应动态切换为 plain。

**目标运行证据**：`mac.tde.dynamic_switch_document_requirement` 在隔离 RC4 集群中成功执行 `ALTER SYSTEM SET tde_encrypt = 'plain'` 和 `pg_reload_conf()`，但 `SHOW tde_encrypt` 仍返回 `rc4`。

**自动化处理**：用例保留文档步骤及 plain 期望，标记为 `D-007` 并保留 FAILED 结果；不以重启替换 reload 掩盖动态切换未生效的问题。

## D-008：商密和TLCP认证转测.md / 2.3.8、2.3.9 / 归档后无法恢复证书

**涉及转测文档和章节**：`商密和TLCP认证转测.md` / `2.3.8 归档证书`、`2.3.9 恢复证书`。

**文档原文**：`2.3.8` 的归档示例后，`2.3.9` 明确要求从 `certs_info_bak`、`key_meta_data_bak` 调用 `restore_certificate(cert_id)` 恢复已销毁并归档的证书。

**目标运行证据**：`mac.tlcp.certificate_lifecycle` 先成功备份 3 条证书和 6 条元数据，随后成功撤销、归档服务端双证书；执行 `restore_certificate((SELECT max(id) FROM fdb_mac.certs_info_bak WHERE useage='server'))` 时，子查询为空而传入 id `0`，实际报 `can not get any cert[id:0] info from certs_info_back.`。

**产品实现**：`contrib/fbase_mac/src/tlcp/fdb_tlcp_meta.c:3308-3313` 在归档路径调用 `fdb_delete_from_cert_info_bak(cert_infos)`；`fdb_tlcp_common.c:4146-4150` 的恢复实现只从 `certs_info_bak` 按 id 查询。因此归档会先删除恢复唯一使用的数据源，归档后恢复不可能成功。

**自动化处理**：用例保留文档的“归档后恢复”顺序，但以当前产品实际失败和活动表为空为断言；
该文档/产品差异记录为 D-008，case 结果为 SUCCESS，并继续执行撤销 CA、归档和活动表清空步骤。
